本站是什么

Brush的离线静态 Wiki： 双击 index.html 即可在浏览器打开，不需要服务器、不联网、不加载任何外部资源 下载后即可独立阅读 —— 本站不引用站点之外的文件，也不指向任何本地路径。

加一个页面

  1. 复制任一现有页面的骨架（<!DOCTYPE html> → <body data-root="../"> → <div id="layout"><aside id="sidebar"></aside><main>…</main></div> → <script src="../assets/nav.js"></script>），写正文；
  2. 到 assets/nav.js 的 NAV 数组里登记一行 { href: 'brush/xxx.html', title: '…' } —— 侧栏完全由 nav.js 生成，页面里不写任何导航；
  3. 根目录的页面写 data-root=""，brush/ 与 api/ 下的页面写 data-root="../"。 写错会让样式与脚本路径失效。

代码高亮

把代码放进 <pre><code>…</code></pre> 即可： highlight.js 会按内容判断语言（Java / Groovy / BAT / JSON / properties）并上色。 判断不出的内容一律保持原样 —— 控制台日志、目录树、Gradle 输出不会被染花。 配色改 style.css 里的 --tok-* 变量即可，明暗两套自动切换。

内容纪律

  • 只写有支撑的结论：代码与类注释是签名与语义的权威；运行时行为以启动日志、 自检报告与实机探针为准。凡属推测、未实测或依赖他人环境的判断，一律显式写「未验证」。
  • 不引用站点之外的文件：正文与页脚都不出现内部文档名或源码路径； 用「项目纪律」「设计文档记载」「实测结论台账」「注入面台账」「源码注释」这类说法替代。
  • 保留读者手上的工程构件名：构建脚本、模组元数据文件、配置属性、 运行目录与日志文件名，以及类名 / 方法名 / 任务名 / 属性名 / 日志原文 —— 这些是读者自己也会看到的东西。
  • 正文不使用解释性括号：正文中的 （…） 一律不写，需要说明就写成正常句子。 单位与数量、标识符标注（代码 / API / 类名 / 命令 / 版本号与编号）、标题与结构名、页脚、代码块不受此限。

保留括号清单

正文里只留下两类括号，其余一律不写：

  • 单位与数量：（约 66 KB）、（394,153 B）、（9 例）、（当前 21 点 / 16 类）。
  • 标识符标注：括号里是代码 / API / 类名 / 方法名 / 命令 / 版本号 / 编号，如 （brush.mod.json）、（S1/S2/S3）、（T1–T4）、（26.10.1）。

此外，代码块、标题与结构名（含导航节名、页名链接文字）与页脚里的括号属于结构位置，不在此口径约束内，全部原样保留。

口径只规定"哪些括号可以留"，不记录逐页数量 —— 数量会随页面更新而漂移，写死在文档里必然过期。要核对某一页，直接读该页正文即可。
