网络

Brush 的网络门面是 BrushNetwork：注册通道、发载荷、收载荷。载荷契约是朴素的字节数组 —— (Identifier, byte[]) 与 (Reply, Identifier, byte[])，mod 侧看不到任何 vanilla 网络类型。三条硬规则：通道必须在主入口点登记、载荷恰好一次且在主线程投递、S3 下通道需要被转登记进 NeoForge。

一、BrushNetwork 公开方法

签名语义
static void register(Identifier channel)注册通道。注册是纯映射写入，任意线程可调用 —— 含 mod 入口构造期。
static void register(Identifier channel, int maxSize)注册通道。throws IllegalArgumentException：通道已注册，或上限越界（1..1048576）。不静默覆盖。
static void send(Identifier channel, byte[] data)经当前连接发送载荷。需在主线程调用。throws IllegalStateException：通道未注册 / 未连接服务器 / 宿主判定不可发送 / 引擎缺席；throws IllegalArgumentException：载荷超长。
static void install(BrushNetwork.Impl implementation)装入引擎实现。你不用调它。
static boolean isInstalled()引擎是否已装入。
interface BrushNetwork.Impl引擎接口：int defaultMaxSize() / void register(Identifier, int) / void send(Identifier, byte[])。实现住库模组 brush-api（org.abstruck.brush.net.BrushNetworkImpl）。

门面为什么这么薄？包归属：org.abstruck.brush.api 是核心模块拥有的包，宿主加载的代码只在该模块里找它、找不到也不回退。于是引擎整体搬进库模组 brush-api，BrushNetwork 留核心当门面，实现经 install(Impl) 装入；另有惰性解析兜底 ⇒ 不依赖任何 mod 的初始化顺序。

作者侧编译面不变：用 BrushNetwork 只需要核心产物 / 契约 jar。只有直接使用引擎内部件才需要库模组产物。

二、通道登记时机：必须在主入口点

这是 S3 的实际教训，不是风格偏好：

public final class ExampleNetworkMod implements BrushModInitializer {
    public static final Identifier HELLO = Identifier.fromNamespaceAndPath("mdkexample", "hello");

    @Override
    public void onInitialize() {                 // <- 主入口点：正确位置
        BrushNetwork.register(HELLO, 4096);
    }
}

NeoForge 只给一次载荷登记机会，宿主适配器在那一刻把"当时已知的通道"桥接进 NeoForge 注册表；而entrypoints.client 的入口点比它晚。在客户端入口点登记的通道在 S3 下发不出去 —— 该情形由发送守卫响亮失败并给出补救指引（S1/S2 无此限制）。这不是推断：宿主实测现场抛过 UnsupportedOperationException: Payload <id> may not be sent to the server!，把登记挪回主入口点后同一场景通过。

一句话规则：通道登记放 onInitialize()，不要放 onInitializeClient()。收包监听器（NETWORK_PAYLOAD / SERVER_PAYLOAD）的订阅时机不受此限。

三、可读的失败

设计意图是"不静默失效"，所以下面每一条都是带指引的异常，而不是难懂的宿主异常或无声丢弃：

情形异常与消息要点
发送未注册的通道IllegalStateException: channel not registered: <id> (call BrushNetwork.register first)
载荷超过该通道上限IllegalArgumentException: payload for <id>: N bytes exceeds channel limit M
未连接服务器IllegalStateException: not connected to a server (check Minecraft.getConnection() != null before sending) —— mod 应把"未连接"当正常状态，发送前自己检查
库模组缺席IllegalStateException: Brush networking is unavailable: the library mod 'brush-api' is not installed in brush-mods/ ... Install brush-api.jar and declare it in your mod's brush.mod.json depends.
重复注册 / 上限越界IllegalArgumentException：channel already registered: <id> / channel <id>: maxSize N out of range 1..1048576
S3 下通道迟到BrushChannels.SendGuard 给出的原因：通道在 NeoForge 载荷注册事件之后才登记，不在 NeoForge 载荷表里、checkPacket 会拒收 ⇒ 给出"从 mod 主入口点登记"的指引

SendGuard 是宿主侧安装的接缝：S1/S2 下守卫为 null；S3 下由桥在 attach 时装上。它让"事件之后登记的通道"变成 Brush 自己的可读硬失败，而不是让 NeoForge 抛难懂的异常，也不是静默失效。

四、载荷事件契约

事件载荷契约方向与线程
BrushEvents.NETWORK_PAYLOADvoid onNetworkPayload(Identifier channel, byte[] data)客户端收。触发线程 = 处理该包的线程；Brush 已统一到主线程投递。
BrushEvents.SERVER_PAYLOADvoid onServerPayload(Reply reply, Identifier channel, byte[] data)服务端收。触发线程 = 服务端网络线程。reply 是回包句柄，可多次调用。
ServerPayloadEvent.Replyvoid send(Identifier channel, byte[] data)向发来该载荷的客户端回包。throws IllegalArgumentException：载荷超过该通道上限。

为什么需要 SERVER_PAYLOAD：只有 send + NETWORK_PAYLOAD 时，网络是单向的 —— 任何"服务器驱动的同步 / 查询"都写不出来，因为回包得构造 vanilla 的 ClientboundCustomPayloadPacket 与核心内部件。而 Reply 的实现由库模组提供，对 mod 只暴露这一个接口 —— 于是"双向"对 mod 而言仍然只有 L2，依赖面里不出现任何 vanilla 网络类型。

data 的所有权
解码时新建的数组，监听器可以安全持有；长度已按通道上限校验。
未注册 id
到不了这两个事件：编码 / 解码链保证未注册 id 走 vanilla 语义，vanilla / 宿主载荷零开销。
回包路径
Reply 内部是"取该通道上限 → 过宿主守卫 → 尺寸 / 注册校验 → 沿服务端连接发 ClientboundCustomPayloadPacket"。
端到端限制：NETWORK_PAYLOAD 覆盖"服务器 → 客户端"的投递。与世界内服务器的完整往返需要服务端存在同名通道对端；专有服务器不在本项目范围。单机世界的集成服务器为 vanilla 代码，未知通道按 vanilla 语义丢弃 —— 这是 vanilla 自定义载荷机制的设计行为，不是故障。非 mod 服务器未实测。未验证

五、投递语义：恰好一次 + 主线程

这不是"顺手做的"，而是实机探针逼出来的两条修正：

  1. vanilla 本地连接会把同一个包处理两次。26.1.2 下集成服务器连接存在"内联 + 排队"双处理 —— 一次在 netty 线程内联（Connection.channelRead0），一次在主线程排队（PacketProcessor.processQueuedPackets ← Minecraft.runTick），两次的 System.identityHashCode(packet) 完全相同。
  2. 因此我们的注入做两件事，都是必需的：按包实例身份去重，以及统一在主线程投递—— 否则 mod 监听器可能在网络线程上跑、直接触碰游戏状态。

去重落在 DispatchDedupe：有界身份窗口，默认保留最近 64 个包对象身份。为什么不是"只记最后一个"：单槽在两个包交错时会漏 —— X 内联认领、Y 内联把 X 顶掉、主线程再处理 X 时槽里是 Y ⇒ X 被派发两次。这个语义由 DispatchDedupeTest（9 例）钉住。代价如实登记：强引用最近 64 个包对象，有界，不随运行时长增长。

这条保证已经变成自动化硬断言：

network: sent=1, observed=100 ticks, alive=yes, kicked=no,
  realTransport=false (isMemoryConnection=true),
  roundTrip: server.pings=1, client.pongs=1 (expected 1/1), mainThread=yes -- result=ok
断言 1
server.pings == 1 —— 服务端钩子生效。
断言 2
client.pongs == 1 —— 恰好一次，失败消息里点名 DispatchDedupe。
断言 3
收到 pong 时 Minecraft.isSameThread() —— 投递在主线程。
实测覆盖
S1、S2 与 S3 三个运行时都有 server.pings=1, client.pongs=1, mainThread=yes 的实机证据。
负向测试
临时短路去重后复跑，断言如期把构建打红并报 client.pongs=2 —— "一个不会失败的断言等于没有断言"。

六、三运行时的差异

运行时通道登记发送与投递
S1 纯 Brush登记进 Brush 通道注册表即可直接可用：编解码经 vanilla 单点 CustomPacketPayload$1#findCodec 的 RETURN 包装接通
S2 Fabric 宿主同上同上。fabric-api 包装的是 findCodec 的调用点，与我们包装的方法体 RETURN 位置不同，任意先后互不抹除；NeoForge 侧 NetworkRegistry.getCodec 在其 miss 分支内，未注册 id 仍会走到我们的包装
S3 NeoForge 宿主同上需先把通道转登记进 NeoForge 载荷表，否则 checkPacket 拒绝发送

转登记由库模组里的 org.abstruck.brush.api.impl.host.NeoForgePayloadBridge 完成：

  • 它挂在宿主的 mod 事件总线的 RegisterPayloadHandlersEvent 上，用 PayloadRegistrar.playBidirectional(type, codec, NOOP, NOOP) 把当时已知的每个 Brush 通道登记为双向载荷（每 id 一条日志：S3 payload bridge: registered channel <id> (maxSize=...)）。
  • handler 是空实现，这是刻意的：登记的唯一目的是让 NeoForge 的 checkPacket 放行；投递仍走我们自己的注入点，与 S1/S2 完全同一条链。若这里再转发一次就会双重投递 —— 实测 server.pings=1, client.pongs=1 把"既无双重投递、也未被宿主截走"钉死。
  • 幂等：attach 只挂一次监听；每个 id 只登记一次。
  • 加载器只把它当 Object 递出：核心经中性接缝把宿主 mod 事件总线当对象交给库模组入口，由库模组自行 attach。于是核心零 mod 类型引用，"引用 NeoForge 类型"这件事落在允许引用宿主类的库模组里；S1/S2 下该类永不加载。
如实登记的边界：① 事件之后才登记的通道不会被桥接；② 事件精确触发点位于 FML loader jar 内，本项目未做字节码直证 —— 但若推断有误，事件到来时通道表为空、什么都注册不上，S3 探针会照旧崩，不会假绿；③ 只覆盖"两侧都跑 NeoForge + 我们的宿主适配器"的实测情形。未验证

七、一段完整的示例：注册通道 + 发一条 + 收一条

主入口负责登记通道与订阅收包：

package com.example.mdk;

import java.nio.charset.StandardCharsets;

import net.minecraft.resources.Identifier;

import org.abstruck.brush.api.BrushEvents;
import org.abstruck.brush.api.BrushModInitializer;
import org.abstruck.brush.api.BrushNetwork;
import org.apache.logging.log4j.LogManager;
import org.apache.logging.log4j.Logger;

public final class ExampleNetworkMod implements BrushModInitializer {

    private static final Logger LOGGER = LogManager.getLogger("mdkexample");

    /** 通道 id 的命名空间用你的 mod id —— 命名冲突由你自己负责。 */
    public static final Identifier HELLO = Identifier.fromNamespaceAndPath("mdkexample", "hello");

    @Override
    public void onInitialize() {
        // ① 登记通道 —— 必须在主入口点
        BrushNetwork.register(HELLO, 4096);   // 4 KiB 上限；不传上限则用默认 1 MiB

        // ② 客户端收包（服务器 -> 客户端）
        BrushEvents.NETWORK_PAYLOAD.register((channel, data) -> {
            if (!HELLO.equals(channel)) {
                return;
            }
            LOGGER.info("[mdkexample] payload received: "
                    + new String(data, StandardCharsets.UTF_8));
        });

        // ③ 服务端收包 + 回包（客户端 -> 服务器 -> 客户端）
        BrushEvents.SERVER_PAYLOAD.register((reply, channel, data) -> {
            if (!HELLO.equals(channel)) {
                return;
            }
            LOGGER.info("[mdkexample] server side got: "
                    + new String(data, StandardCharsets.UTF_8));
            reply.send(HELLO, "pong".getBytes(StandardCharsets.UTF_8));
        });
    }
}

客户端入口只负责发，并且把"未连接"当正常状态处理：

package com.example.mdk;

import java.nio.charset.StandardCharsets;

import net.minecraft.client.Minecraft;

import org.abstruck.brush.api.BrushClientModInitializer;
import org.abstruck.brush.api.BrushEvents;
import org.abstruck.brush.api.BrushNetwork;
import org.apache.logging.log4j.LogManager;
import org.apache.logging.log4j.Logger;

public final class ExampleNetworkClient implements BrushClientModInitializer {

    private static final Logger LOGGER = LogManager.getLogger("mdkexample");

    /** 只发一次（进入世界、连接就绪后的首个 tick）。 */
    private static boolean sent;

    @Override
    public void onInitializeClient() {
        BrushEvents.CLIENT_TICK.register(event -> {
            if (sent) {
                return;
            }
            Minecraft minecraft = Minecraft.getInstance();
            if (minecraft == null || minecraft.getConnection() == null) {
                return;   // 未连接 = 正常状态，等下一 tick
            }
            sent = true;
            try {
                BrushNetwork.send(ExampleNetworkMod.HELLO,
                        "ping".getBytes(StandardCharsets.UTF_8));
                LOGGER.info("[mdkexample] ping sent on " + ExampleNetworkMod.HELLO);
            } catch (RuntimeException e) {
                LOGGER.warn("[mdkexample] ping send failed: " + e);
            }
        });
    }
}

执行顺序：onInitialize() 登记通道并订阅监听器 → S3 下宿主载荷事件到来时桥接已知通道 → 进入世界后 CLIENT_TICK 里发一次 → 服务端侧 SERVER_PAYLOAD 回包 → 客户端侧 NETWORK_PAYLOAD 收到，两者都已在主线程上被调用。
