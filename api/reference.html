API 参考索引

本页是工具页：把 org.abstruck.brush.api 包里的每个公开类型列成表，标注种类与"作者是否应该直接用"；再单独说明库模组的 impl 包为什么不在契约面里。最后是一张「常见任务 → 用哪个 API」速查表。

本页怎么读："作者应直接用？"这一列按编译面判断，不是按"类是不是 public"判断 —— 作者的编译面是 brush-api-contract.jar，其中契约面内的类型一律为"是"，仅供加载器与库模组内部使用的接缝标"否"。四类顶层类型的分工是：入口与钩子、事件入口与事件类型、注册与内容门面、工具类型。包内唯一不公开的类是 CreativeTabEntriesImpl，它只是 CreativeTabEntries 的实现，不出现在下表。
计数口径：org.abstruck.brush.api 包下共 40 个源文件，其中包私有实现类 1 个，其余 40 个顶层公开类型+ 14 个公开嵌套类型 = 公开类型合计 54 个。下表逐行列出这 54 个类型（顶层 40 + 嵌套 14），共 54 行—— 与 40 个顶层类型 + 14 个公开嵌套类型的清点结果一致，无遗漏。

1. 作者入口与生命周期钩子

类型名种类一句话职责作者应直接用？
BrushModInitializer接口主入口：onInitialize() 在 bootstrap.early 锚点、游戏代码运行之前调用是 —— entrypoints.main 的类必须实现
BrushClientModInitializer接口客户端入口：onInitializeClient() 在 Minecraft#run() HEAD、首个 tick 与 CLIENT_READY 之前调用是 —— 需要客户端实例时实现（entrypoints.client）
BrushDedicatedServerModInitializer接口专用服务端入口契约占位：当前只被校验、不被派发可以声明，但实现它不会在任何现有运行时被调用

6. impl 包：不在契约面里

结论：org.abstruck.brush.api.impl 不属于作者契约面。作者的编译面是 brush-api-contract.jar，它只含 org/abstruck/brush/api/**，显式排除 org/abstruck/brush/api/impl/**，并在构建时机械校验"产物里只能有 api 包下的条目，且不得是 impl 实现"。

在 jar 版 MDK里没有契约 jar：作者的编译面就是 libs/ 下那两份 jar 所提供的 org.abstruck.brush.api.**。也就是说，能依赖的只有 api 包；org.abstruck.brush.api.impl 是能力库的内部实现，不要依赖 —— 它随版本变动，不属于契约。契约 jar 仍存在于完整的加载器项目里，供想机械地把自己约束在契约面上的作者使用。

为什么它们必须住在库模组

设计文档记下的结论是：网络引擎 + S3 载荷桥 + mixin 属实现，加载器只留门面与接缝。具体拆成四条理由：

  1. 这些是"游戏能力"，不是加载器本职。对照 Fabric 世界的分工：Fabric Loader 只做基础设施，Fabric API 才是能力库。loader 只留"门面与接缝"。
  2. 它们与 vanilla 强耦合，天然要碰 L1。能力实现与它的注入点无法同时避开 L1；库模组作为第一方产物被允许引用 L1，这是拆分可行的前提。反过来，把这些注入点留在核心会让核心的 footprint 变大。
  3. 搬家是"物理搬家"，不是重写。引擎类保持原包名与类名（org.abstruck.brush.net.*），所以 mod 作者的 import 一行都不用改；注入面闸门机械证明"总数不变、只是归属变了"。
  4. 但 BrushNetwork 这个门面必须留在核心。这是搬家撞出的真回归：org.abstruck.brush.api 是核心模块拥有的包，宿主（FML）加载的代码只会在该模块里找这个包下的类，找不到也不会回退到我们的加载器 —— 整类搬走会在 S3 实机崩（NoClassDefFoundError: org/abstruck/brush/api/BrushNetwork）。修正方式是把 BrushNetwork 降为一层门面，实现 BrushNetworkImpl 住库模组。由此得到一条可复用判据：核心 → mod 搬家时，"包归属"与技术可行性同等重要。
对作者的实际影响：编译面不变。用 BrushNetwork 只需核心产物 / 契约 jar；只有直接用引擎内部件才需要库模组产物 —— 而那不是契约面。

7. 常见任务 → 用哪个 API

常见任务用哪个 API细节页
注册一个物品BrushEvents.CONTENT_REGISTRATION 监听器内调 BrushRegistry.registerItem(id, properties)内容注册
注册一个方块同上窗口内调 BrushRegistry.registerBlock(id, factory, properties)；"有方块无物品"用 registerBlockWithoutItem内容注册
发一条自定义载荷主入口里 BrushNetwork.register(id)；发送 BrushNetwork.send(id, bytes)；接收订阅 BrushEvents.NETWORK_PAYLOAD；要回包用 BrushEvents.SERVER_PAYLOAD + ServerPayloadEvent.Reply网络
每帧做事订阅 BrushEvents.CLIENT_TICK 或 BrushEvents.HUD_EXTRACT事件总表
加标题界面按钮订阅 BrushEvents.SCREEN_INIT，在监听器里判断 screen instanceof TitleScreen 后加 widget；窗口缩放另一条路径订阅 SCREEN_RESIZE界面与输入
读别人的 mod 元数据BrushMods.list() / BrushMods.find(id) / BrushMods.isLoaded(id)；加载器与游戏版本用 loaderVersion() / gameVersion()本页 §3
